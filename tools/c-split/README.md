# c-split

Splits one C file generated by rc2 into a shared header and several
parts, so the C compiler takes the program in pieces instead of in one
translation unit.

rc2 writes a whole program as one `.c` file. For the self-hosted compiler
(`rc2-norepl.ipkg`) that file is 111 MB, and `clang -O2` takes it in
about 9 minutes at a peak of 2.2 GB, while the rc2 process that called it
waits. Split into parts, each part takes a fraction of that memory, and the
parts compile in parallel.

```
$ c-split [--part-bytes N] [--commands INPUT.cmd] INPUT.c OUTDIR
OUTDIR/INPUT-0.c
OUTDIR/INPUT-1.c
...
```

It writes `OUTDIR/INPUT.h` and the parts, and prints the parts one per
line. Each part starts with `#include "INPUT.h"`; compile each with the
flags the whole file would have had, and merge the objects into the one
object the whole file would have made (see "The Makefile"). `--part-bytes`
(default 4,000,000) is the size a part grows to before the next cut.

With `--commands`, it also writes `OUTDIR/Makefile` (below).

Exit code `0` when it split, `1` when the input is outside what it splits
(the reason on stderr; compile the file whole instead), `2` on a usage or
file error.

It is for rc2's output, not for any C: see "What it refuses" below.

## How the input is read

The input is read into one buffer and scanned byte by byte, never copied
into strings or lists: the 111 MB file takes 16 s and a peak of 240 MB.
The scanner skips comments and string and character literals, counts the
depth of `()`, `[]` and `{}`, and cuts the file into top-level items:

- a **preprocessor line** (`#` first on a line, at depth 0, continued by
  a trailing backslash);
- a **function definition**: a `{` at depth 0 right after a `)`, and before
  any `=` (so `T x = (T){ ... };` stays data), up to its matching `}`;
- a **data definition**: a `;` at depth 0 after an `=` at depth 0;
- a **declaration**: any other `;` at depth 0 (prototypes, `extern`,
  `typedef`, struct definitions, tentative definitions, an empty `;`).

A preprocessor line inside a function body is part of the body; its text is
not scanned for literals. The blanks and comments in front of an item belong
to it, so the items put back together in order are the input.

A part reaches a function of another part through the prototype in the
header, so every function used across parts needs one before it is used.
rc2 writes a prototype for every function first.

## Where each item goes

| Item | Header | Part |
|---|---|---|
| preprocessor line, declaration | as is | |
| `static` prototype | `static` replaced by `RC2SPLIT_LOCAL` | |
| `static inline` function | as is (a copy in every part) | |
| function definition | | as is |
| `static` function definition | | `static` replaced by `RC2SPLIT_LOCAL` |
| data definition | `extern` declaration | as is |
| `static` data definition | `extern RC2SPLIT_LOCAL` declaration | `static` replaced by `RC2SPLIT_LOCAL` |
| tentative definition (`char const name[];`) | `extern` declaration | the first part, if no data definition of the name exists |

`RC2SPLIT_LOCAL` is `__attribute__((visibility("hidden")))`, defined at the
top of the header.

### Why `static` becomes hidden, not duplicated

A part must reach what another part defines, so whatever was `static` gets
external linkage, with exactly one definition. A copy per part instead
would multiply the 11,000 constants of the self-hosted compiler and break
the identity of a constant's address. Every program rc2 builds has its own
`constcon_131`, so these names must not leave the program: two rc2 libraries
in one host would bind each other's. Hidden visibility marks them, and the
merge of the parts' objects makes them local again (`objcopy
--localize-hidden`), so the object is what the whole file would have given.

### Tentative definitions

`char const idris2rc2_constr_X[];` without `extern` is a definition in every
translation unit that sees it, and with `-fno-common` (the default) two of
them do not link. The header declares it `extern`; the definition stays
where the input defines it.

### Constants of an anonymous struct type

rc2 gives a constant constructor of more than 20 fields or without a tag,
and a constant closure over more than 20 values, a type of its own:
`static struct { ... } const constcon_N = ...;` (`Emit/Util.idr`).
Two anonymous struct types in one translation unit are two types, so the
part that defines it could not also see an `extern` with its own copy of the
struct. The header names the type, `typedef struct { ... } rc2split_t_constcon_N;`,
and both the declaration and the definition use that name.

## Where the cuts go

Parts are contiguous runs of the input, in order. A cut goes in front of a
function or data definition once the definitions in the current part have
`--part-bytes` and the last of them was a function. rc2 writes the constants a function stages
right in front of it, so a function and its constants stay in one part.

The header holds every declaration of the program: 2.8 MB for the
self-hosted compiler, which a translation unit with nothing else compiles in
1.3 s at 120 MB.

## What it refuses

It stops with exit code 1, before writing anything, when it meets:

- a preprocessor line after the first definition (a `#if` or `#define`
  between functions could not be moved into the header), or inside an item
  outside a function body;
- a `static` variable without an initializer;
- an `inline` function that is not `static`;
- a variable of a struct, union or enum type without an initializer, or one
  declared together with the type (`struct S { ... } v;`);
- a variable of a function pointer type without an initializer;
- an item that starts with a compiler extension (`__attribute__`, `__asm__`);
- a data definition whose type block is not an anonymous struct, or whose
  name is not found;
- an item that does not start with an identifier, or unbalanced brackets.

None of these occur in rc2's output; `extraRuntime`/`inlineRuntime` text is
the user's, and gets the same checks.

## The Makefile

rc2 writes its own compile and link commands with `--directive writecc`, to
`INPUT.cmd` next to the `.c`, and `--directive nocc` stops it before it runs
them (`rc2/doc/directives.md`):

```
$ idris2-rc2 --cg rc2 --directive writecc --directive nocc Main.idr -o prog
$ c-split --commands build/exec/prog.cmd build/exec/prog.c build/split
$ make -C build/split -j4
```

The Makefile has one rule per part, `INPUT-K.o: INPUT-K.c INPUT.h`, whose
recipe is rc2's compile command with the part in place of the whole `.c`
and `INPUT-K.o` in place of its object. `all` then makes the object rc2's
final command takes from the parts' objects, and runs that command as rc2
wrote it, so an executable, a `staticlib` and a `sharedlib` are built alike:

1. `ld -r` merges the parts' objects into one;
2. `objcopy --localize-hidden` makes local what was `static` (see above);
3. `ld -r --gc-sections`, from every global symbol (`nm`, then `awk`, in two
   steps so that a failing `nm` stops make), drops what was `static` and is
   not used. In one translation unit the C compiler leaves such a
   function out; split, it is compiled, and its calls stay as undefined
   symbols, which a shared library loaded with `dlopen` does not resolve.

`clean` removes what the Makefile built: the parts' objects, the merged
object and its intermediate files, and what the final command makes (its
`-o`, or the archive of `ar rcs`). The header and the parts stay, as c-split
wrote them.

Each recipe first changes to the directory rc2 ran in, since rc2's commands
name files relative to it, and keeps the flags rc2 took from `IDRIS2_CFLAGS`
and the like as they were. It needs `ld`, `objcopy`, `nm` and `awk`.
The arguments are found as rc2 quotes them (`System.Escape.escapeArg`), so
a command that does not name the source or the object is refused, and so
is a part path a make target cannot hold (a blank or one of `:#$%*?[\`).

`make -j N` runs N compilers at once. For rc2's self-hosted compiler a part
takes under 300 MB with `clang -O2`.

## Results (2026-11-20)

The self-hosted compiler (`rc2-norepl.ipkg`, 111 MB of C, 4 cores):

| | Wall time | Peak of the C compiler |
|---|---|---|
| one `clang -O2` | about 9 min | 2.2 GB |
| `c-split` | 12-16 s | (the tool itself: 240 MB) |
| 28 parts, `make -j4` | about 5 min | 0.95 GB in all, 275 MB the largest part |

The compiler built from the parts generates its own C byte for byte as the
Chez-built rc2 does.

Every program of `rc2/tests` and `rc2/tests/bench` (122) split into parts of
2,000 bytes, built through the Makefile and run, prints what the unsplit
build prints; so do the library tests (`rc2/tests/library`: two static and
two shared libraries in one host, `dlopen`, an rc2 host).

### What the parts cost at run time

A call from one part to another is not inlined (no link-time optimization).

- The self-hosted compiler in 28 parts, compiling a program (`perf stat -i`,
  the compiler alone): instructions +0.8%, cycles -0.1% to -0.5%, on
  `Test111Basics` and `Test168NumericEdge`.
- The benchmarks in parts of 2,000 bytes, the worst case: most within noise,
  but `BenchPtrFn` takes 47 times the instructions, and `BenchKnownCon` and
  `BenchPushCon` 1.9 times: their loop calls a function the C compiler
  inlined, and folded into the loop, in one translation unit. At the default
  `--part-bytes` they are one part, as is any small program.

Splitting is for a program whose one translation unit costs too much to
compile; a hot loop and what it calls can land in two parts.

## Tests

`tests/verify.sh` builds the tool and checks it on hand-written C: one file
with every kind of item it rewrites, split after every function, must compile
with `-Wall -Werror` and print what the unsplit program prints, also through
the Makefile of a command file shaped like rc2's (what was `static` must be
local in the merged object, and `clean` must leave only the parts); each
`refuse-*.c` must be refused.
