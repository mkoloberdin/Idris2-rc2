# c-split

*[English](README.md)*

rc2が生成した1つのCファイルを、共有ヘッダと複数のパートに分割します。これにより、Cコンパイラはプログラム全体を1つの翻訳単位としてではなく、小分けにして処理できます。

rc2は、プログラム全体を1つの`.c`ファイルとして書き出します。セルフホスティングしたコンパイラ（`rc2-norepl.ipkg`）では、このファイルが111 MBになり、`clang -O2`で約9分、ピーク2.2 GBのメモリを使ってコンパイルします。そのあいだ、`clang`を呼んだrc2のプロセスは待たされます。パートに分けると、各パートに必要なメモリはその何分の一かで済み、パートは並列にコンパイルできます。

```
$ c-split [--part-bytes N] [--commands INPUT.cmd] INPUT.c OUTDIR
OUTDIR/INPUT-0.c
OUTDIR/INPUT-1.c
...
```

`OUTDIR/INPUT.h`とパートを書き出し、パートを1行に1つずつ出力します。各パートの先頭は`#include "INPUT.h"`です。各パートは、ファイル全体をコンパイルしたときと同じフラグでコンパイルし、そのオブジェクトをマージして、ファイル全体から得られるはずの1つのオブジェクトにします（「Makefile」を参照）。`--part-bytes`（既定値は4,000,000）は、次の切れ目を入れるまでにパートが大きくなってよいサイズです。

`--commands`を指定すると、`OUTDIR/Makefile`も書き出します（後述）。

終了コードは、分割できたときが`0`、入力が分割の対象外だったときが`1`（理由はstderrに出ます。その場合はファイルを丸ごとコンパイルしてください）、使い方またはファイルのエラーが`2`です。

対象はrc2の出力であり、任意のCではありません。後述の「拒否するもの」を参照してください。

## 入力の読み方

入力は1つのバッファに読み込み、1バイトずつ走査します。文字列やリストにコピーすることはなく、111 MBのファイルで16秒、ピーク240 MBです。スキャナはコメントと文字列・文字リテラルを読み飛ばし、`()`、`[]`、`{}`の深さを数えて、ファイルをトップレベルの項目に切り分けます。

- **プリプロセッサ行**: 深さ0で行頭に`#`があるもの。行末のバックスラッシュで継続します。
- **関数定義**: 深さ0で`)`の直後、かつ`=`より前にある`{`から、対応する`}`まで（`T x = (T){ ... };`はデータのままです）。
- **データ定義**: 深さ0の`=`のあとにある、深さ0の`;`。
- **宣言**: 深さ0のそれ以外の`;`（プロトタイプ、`extern`、`typedef`、構造体定義、仮定義、空の`;`）。

関数本体の中のプリプロセッサ行は本体の一部であり、そのテキストはリテラルの走査対象になりません。項目の前にある空白とコメントはその項目に属するので、項目を順に戻せば入力になります。

パートは、ヘッダにあるプロトタイプを通して、別のパートの関数に到達します。したがって、パートをまたいで使われる関数にはすべて、使われる前にプロトタイプが必要です。rc2は、すべての関数のプロトタイプを先頭にまとめて書きます。

## 各項目の行き先

| 項目 | ヘッダ | パート |
|---|---|---|
| プリプロセッサ行、宣言 | そのまま | |
| `static`のプロトタイプ | `static`を`RC2SPLIT_LOCAL`に置換 | |
| `static inline`関数 | そのまま（すべてのパートにコピー） | |
| 関数定義 | | そのまま |
| `static`の関数定義 | | `static`を`RC2SPLIT_LOCAL`に置換 |
| データ定義 | `extern`宣言 | そのまま |
| `static`のデータ定義 | `extern RC2SPLIT_LOCAL`宣言 | `static`を`RC2SPLIT_LOCAL`に置換 |
| 仮定義（`char const name[];`） | `extern`宣言 | その名前のデータ定義がなければ、最初のパート |

`RC2SPLIT_LOCAL`は`__attribute__((visibility("hidden")))`で、ヘッダの先頭で定義します。

### `static`を複製せずhiddenにする理由

パートは、別のパートが定義するものに到達できなければなりません。そのため、`static`だったものは、定義を1つだけ持つ外部結合になります。代わりにパートごとにコピーを持たせると、セルフホスティングしたコンパイラの11,000個の定数が増えてしまい、定数のアドレスの同一性も壊れます。rc2が作るプログラムにはどれも固有の`constcon_131`があるので、これらの名前はプログラムの外へ出てはいけません。1つのホストに2つのrc2ライブラリがあると、互いの名前を束縛してしまうからです。hidden可視性でこれらに印を付け、パートのオブジェクトをマージしたあとで再びローカルにします（`objcopy --localize-hidden`）。これにより、できあがるオブジェクトはファイル全体から得られるものと同じになります。

### 仮定義

`extern`のない`char const idris2rc2_constr_X[];`は、それが見えるすべての翻訳単位で定義になります。`-fno-common`（既定値）では、2つあるとリンクできません。ヘッダはこれを`extern`で宣言し、定義は入力が定義している場所に残します。

### 無名構造体型の定数

rc2は、フィールドが20個を超える定数コンストラクタ、タグのない定数コンストラクタ、および20個を超える値を捕捉する定数クロージャに、専用の型を与えます。`static struct { ... } const constcon_N = ...;`という形です（`Emit/Util.idr`）。1つの翻訳単位にある2つの無名構造体型は、別の型になります。そのため、これを定義するパートが、構造体の自前のコピーを持つ`extern`も同時に見ることはできません。ヘッダは`typedef struct { ... } rc2split_t_constcon_N;`で型に名前を付け、宣言と定義の両方がその名前を使います。

## 切れ目の入れ方

パートは、入力を順に区切った連続した範囲です。現在のパートの定義が`--part-bytes`に達し、その最後が関数であったときに、次の関数定義またはデータ定義の前に切れ目を入れます。rc2は、関数が用意する定数をその関数の直前に書くので、関数とその定数は同じパートに収まります。

ヘッダにはプログラムのすべての宣言が入ります。セルフホスティングしたコンパイラでは2.8 MBで、ほかに何もない翻訳単位としてコンパイルすると、1.3秒、120 MBです。

## 拒否するもの

次のものに出会うと、何も書き出す前に終了コード1で止まります。

- 最初の定義より後にあるプリプロセッサ行（関数と関数のあいだの`#if`や`#define`は、ヘッダに移せません）、または関数本体の外にある項目の内側のプリプロセッサ行。
- 初期化子のない`static`変数。
- `static`でない`inline`関数。
- 初期化子のない、構造体・共用体・列挙型の変数、または型と同時に宣言された変数（`struct S { ... } v;`）。
- 初期化子のない、関数ポインタ型の変数。
- コンパイラ拡張（`__attribute__`、`__asm__`）で始まる項目。
- 型のブロックが無名構造体でない、または名前が見つからないデータ定義。
- 識別子で始まらない項目、または括弧の対応が取れていない項目。

rc2の出力にこれらが現れることはありません。`extraRuntime`/`inlineRuntime`のテキストはユーザーが書くものであり、同じ検査を受けます。

## Makefile

rc2は、`--directive writecc`で、自分のコンパイルコマンドとリンクコマンドを`.c`の隣の`INPUT.cmd`に書き出します。`--directive nocc`を指定すると、rc2はそれを実行する前に止まります（`rc2/doc/directives.md`）。

```
$ idris2-rc2 --cg rc2 --directive writecc --directive nocc Main.idr -o prog
$ c-split --commands build/exec/prog.cmd build/exec/prog.c build/split
$ make -C build/split -j4
```

Makefileには、パートごとに`INPUT-K.o: INPUT-K.c INPUT.h`というルールが1つあります。レシピは、rc2のコンパイルコマンドの、`.c`全体をそのパートに、オブジェクトを`INPUT-K.o`に置き換えたものです。`all`は、rc2の最終コマンドがパートのオブジェクトから取るオブジェクトを作り、そのコマンドをrc2が書いたとおりに実行します。そのため、実行ファイル、`staticlib`、`sharedlib`のどれも同じ方法でビルドできます。

1. `ld -r`で、パートのオブジェクトを1つにマージします。
2. `objcopy --localize-hidden`で、`static`だったものをローカルにします（上記を参照）。
3. `ld -r --gc-sections`で、すべてのグローバルシンボルを起点に、`static`だったもののうち使われないものを取り除きます（`nm`と`awk`を2段階に分けてあるのは、`nm`が失敗したときにmakeが止まるようにするためです）。1つの翻訳単位であれば、Cコンパイラはそのような関数を出力しません。分割するとそれもコンパイルされ、その呼び出しが未定義シンボルのまま残ります。`dlopen`で読み込む共有ライブラリでは、これが解決されません。

`clean`は、Makefileが作ったものを削除します。パートのオブジェクト、マージしたオブジェクトとその中間ファイル、最終コマンドが作るもの（その`-o`、または`ar rcs`のアーカイブ）です。ヘッダとパートは、c-splitが書いたまま残ります。

各レシピは、まずrc2が実行されたディレクトリに移動します。rc2のコマンドはファイルをそこからの相対パスで名指すからです。また、rc2が`IDRIS2_CFLAGS`などから取ったフラグはそのまま保ちます。`ld`、`objcopy`、`nm`、`awk`が必要です。引数は、rc2が引用したとおりの形（`System.Escape.escapeArg`）で探します。したがって、ソースもオブジェクトも名指さないコマンドは拒否されます。makeのターゲットに置けないパートのパス（空白、または`:#$%*?[\`のいずれかを含むもの）も同様です。

`make -j N`は、N個のコンパイラを同時に走らせます。rc2のセルフホスティングしたコンパイラでは、`clang -O2`で1パートあたり300 MB未満です。

## 結果（2026-11-20）

セルフホスティングしたコンパイラ（`rc2-norepl.ipkg`、Cで111 MB、4コア）です。

| | 実時間 | Cコンパイラのピーク |
|---|---|---|
| `clang -O2`を1回 | 約9分 | 2.2 GB |
| `c-split` | 12〜16秒 | （ツール自身: 240 MB） |
| 28パート、`make -j4` | 約5分 | 全体で0.95 GB、最大のパートは275 MB |

パートからビルドしたコンパイラは、Chezでビルドしたrc2と同じCを、バイト単位で一致して生成します。

`rc2/tests`と`rc2/tests/bench`のすべてのプログラム（122個）を2,000バイトのパートに分割し、Makefileでビルドして実行すると、分割しないビルドと同じ出力になります。ライブラリのテスト（`rc2/tests/library`: 1つのホストにある2つの静的ライブラリと2つの共有ライブラリ、`dlopen`、rc2のホスト）も同様です。

### パートの実行時コスト

あるパートから別のパートへの呼び出しはインライン化されません（リンク時最適化は使っていません）。

- 28パートに分けたセルフホスティングコンパイラでプログラムをコンパイルした場合（`perf stat -i`、コンパイラ単体）、`Test111Basics`と`Test168NumericEdge`では、命令数が+0.8%、サイクル数が-0.1%〜-0.5%でした。
- 2,000バイトのパート（最悪のケース）でのベンチマークは、大半が誤差の範囲に収まります。ただし、`BenchPtrFn`は命令数が47倍に、`BenchKnownCon`と`BenchPushCon`は1.9倍になります。これらのループは、1つの翻訳単位ではCコンパイラがインライン化してループに畳み込んでいた関数を呼ぶからです。既定の`--part-bytes`では、これらも、小さなプログラムはどれも、1つのパートになります。

分割は、1つの翻訳単位のコンパイルが高くつきすぎるプログラムのためのものです。ホットなループとそれが呼ぶ関数が、2つのパートに分かれてしまうことがあります。

## テスト

`tests/verify.sh`は、ツールをビルドして、手書きのCで検査します。書き換える種類の項目をすべて含む1つのファイルを、関数ごとに分割します。その結果は、`-Wall -Werror`でコンパイルでき、分割しないプログラムと同じ出力になる必要があります。rc2と同じ形のコマンドファイルのMakefileを通した場合も同様です（`static`だったものはマージしたオブジェクトでローカルになっていること、`clean`のあとにパートだけが残ることを確かめます）。`refuse-*.c`は、それぞれ拒否されなければなりません。
